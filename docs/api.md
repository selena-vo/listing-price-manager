# API Contract — docs/api.md

> Source of truth: SPEC.md §6. All endpoints return/accept **JSON**. Base URL: `/api` (dev: `http://localhost:3000` — same Next.js server).
> Implemented as **Next.js route handlers** under `app/api/` (Next.js SaaS Starter base); data access via Drizzle + Postgres (`lib/db/`).
> **The API returns raw values only** (listed price, commission %, rule, campaigns). Guest price / net are computed client-side with the shared rule engine (`lib/pricing/rule-engine.ts` → `computePrice`), so preview (S2) and dashboard (S1) always agree.
> Auth note (MVP): the starter's JWT middleware protects `/dashboard` pages; the price-manager API routes below require no session in the MVP (SPEC §9 Q2 — single shared workspace).

## Conventions

- IDs: integers, generated by the DB.
- Dates: ISO-8601 strings (`"2026-09-01T00:00:00.000Z"`).
- Money: integer **VND** (no decimals) — Q4 confirmed.
- Error response shape:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "pricePerNight must be > 0" } }
```

- Status codes: `200` OK · `201` Created · `204` No Content · `400` validation · `404` not found · `409` conflict (e.g. duplicate platform name).

## Platforms

| Method | Path | Body / notes | Response |
|---|---|---|---|
| GET | `/api/platforms` | — | `Platform[]` (each incl. `campaigns`) |
| POST | `/api/platforms` | `{ name, color?, commissionRate?, discountRule?, sortOrder? }` — defaults: commissionRate 15, discountRule `sum` | `Platform` (201) |
| PATCH | `/api/platforms/:id` | any subset: `{ name?, color?, commissionRate?, discountRule?, sortOrder? }` | `Platform` |
| DELETE | `/api/platforms/:id` | cascade: removes its campaigns **and** the listing prices that reference it | 204 |

`discountRule` enum: `sum` | `best` | `priority` | `sequential`. `commissionRate`: number 0–100. `name`: unique, non-empty.

**Preset helper:** `POST /api/platforms/presets/:key` with `key` ∈ `airbnb` | `booking` | `trip` seeds the reference config from SPEC §4 (Airbnb → `priority` + priority mapping, Booking → `sequential`, Trip → `sum`); the client may also just `POST /api/platforms` with explicit values.

## Campaigns

| Method | Path | Body / notes | Response |
|---|---|---|---|
| POST | `/api/platforms/:platformId/campaigns` | `{ name, discountPercent, active?, priorityOrder?, type?, startsAt?, endsAt? }` — `active` default false; `discountPercent` 0–100 | `Campaign` (201) |
| PATCH | `/api/campaigns/:id` | any subset of the above | `Campaign` |
| DELETE | `/api/campaigns/:id` | — | 204 |

`type` (optional, metadata only — SPEC §5): `new_listing` | `custom` | `length_of_stay` | `early_bird` | `last_minute` | `other`.
`priorityOrder`: integer ≥ 1, 1 = highest; used by `priority` / `sequential` rules.

## Shared rule engine (used by web UI — SPEC §6)

`computePrice({ listedPrice, commissionRate, rule, campaigns, now? })` in `lib/pricing/rule-engine.ts` returns:

```ts
{
  totalDiscount: number,   // % (for `sequential`: effective equivalent)
  guestPrice: number,      // listed × (1 − totalDiscount/100)  — or sequential product
  commission: number,      // guestPrice × commissionRate/100
  net: number,             // guestPrice − commission
  winningCampaignId: number | null  // only for `priority` (Airbnb single winner)
}
```

Tests for all four rules live in `lib/pricing/rule-engine.test.ts` (SPEC §7 criterion "switch rule … recalculates correctly").
